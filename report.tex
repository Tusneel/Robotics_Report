\section{Introduction}

\section{Introduction}

For this project our group has created a robot
in Gazebo Harmonic \cite{gazebodocs} using ROS2 (Robot Operating System 2) \cite{ros2} that can traverse from the
start of a building (Meston in an case of our simulation) to an end goal
whilst avoiding fire. To help it on its journey
it has various sensors such as a camera, a thermometer
and is equipped fire extinguisher. The robot builds a path using an implementation of the A* 
search algorithm, if it runs into an obstacle it 
will use the same algorithm to reroute until it either 
reaches the goal or determines there is no valid path 
to the goal and instead returns to the start.

\section{Task}

The main objective of this was initially to compare two 
different search algorithms, BFS and DFS, to see which 
one would make it to the end quicker but found the search 
algorithms to be to simple and inefficient for the task. 
Thus our task evolved into traversing a building where our robot has make 
it from an initial state to an end goal whilst navigating fiery obstacles using its sensors. 
If it finds there is a path blocked it will be able to use its fire extinguisher once to extinguish a fire. 
However, if both paths prove inaccessible it is able to identify this and instead navigate back to the start. 
Finally, if there is a path unblocked, it will make its way through 
to reach the goal.
With this new task in mind, we decided to take a step back and evaluate the problem as if it were an agent from our artificial intelligence course.
This was because there were notable parallels between our planned simulation and an agent traversing an inaccessible, non-deterministic and dynamic environment. 
This was due to the environment not being fully known to our robot (the agent) upon entrance, the agents also actions wont always result in a success due to the existence of obstacles (fires) and our robot is able to interact and change its environment using the fire extinguisher. This evolved further with our robot initially being given information on its environment, via a fire escape map, making it briefly omnipotent to the environment and leading us to make the decision to swap to using A* heuristic search using the robots distance to the final goal as our heuristic. This also had the benifit of being a notably more efficient search algorithm which was fitting for the environment. Quite frankly it didn't make sense to use two slow search algorithms in a burning building. 

\section{Simulation Environment}

For the environment, we used the fire escape map of Meston and brought 
it into Gazebo. We specifically chose the ground floor for the sake of 
having a flat surface so we wouldn't have to worry about elevation. 
Another change we made was to make the fire static. We attempted to use 
Conway's game of life to determine the robots movement but decided it 
wasn't the best use for it. It didn't make the fire dynamic in any way 
that was meaningful. As such we had settled on static fire on the ground 
floor of the Meston building. This fulfilled our needs as it had more than 
one path to the goal and we didn't have to worry about stairs allowing 
our robots movement to be more straightforward and we didn't have to worry about 
dealing with multiple floors in Gazebo. 

\section{Libraries and Tools}
Our project used ROS2-jazzy with the Gazebo simulation enviroment. In order to develop with ROS we used the rclpy python API 
also provided by Open Robotics. Gazebo provided an easy framework for modifying the robot 
we found, with the robot and world being written using custom XML files, and 
provided a set of useful custom sensors that we used such as the RGBD Camera. 
In addition to these we also used RVIZ \cite{rviz} to visualise our ROS nodes and topics which helped 
with debugging.

\section{Discussion}

\subsection{Strengths}
The most major strength of our robot design is its resilience and ability 
to re-evaluate its approach when something goes wrong. For example, when 
our robot's plan puts it in harms way, it is able to acknowledge this, reverse 
out of danger and then, when safe, create a new plan taking into account its new 
found knowledge of the environment. 

\subsection{Limitations}
The major limitations of our robot consist of; the design, currently our model is 
extremely ditsy and clumsy due to it only having two wheels. Ideally we would like 
to add a third or even forth wheel, tho this is discussed further in the next section. 
Additionally, it is slightly tailored to our Meston domain as it was unfeasible for us 
to model the intricacies of a real burning building thus it may fail in other more expanded 
enviornments. 


\subsection{Future Work}
Given more time, there are several directions in which we would like to extend this project. 
On the search side, we would explore further uninformed search algorithms and compare how different heuristics affect the efficiency of our A* search.
Machine learning techniques could also be investigated as a way of improving the robot's decision-making. 
On the hardware side, testing alternative sensors and robot designs would show how each design changes the way the robot navigates its environment.
The fire itself could be made more realistic by modelling its spread with a cellular automaton such as Conway's Game of Life, 
so that it develops over time rather than remaining static, and the detection and extinguishing system could be developed further to make the robot more effective in realistic scenarios.
We would also like to analyse how the robot performs under different environmental conditions and how well it adapts to them. 
Finally, we would test our software on a physical robot in a real environment, which would show how much the code would need to change to cope with the inconsistencies of a non-simulated world.

\section{Conclusion}
In conclusion, our robot can successfully navigate the partially observable environment we provide it with. 
We achieved this using ros2 and modelling the problem in gazebo. 
Finally, we have many aspects of this project we would love to expand upon given additional time and resources.
